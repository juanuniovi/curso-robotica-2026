Guía de GitHub Desktop

GitHub Desktop permite trabajar con el repositorio del curso sin usar la línea de comandos. El ciclo de cada sesión es: Fetch y Pull al empezar, trabajo en tus archivos, Commit y Push al terminar.

1. Instalación (una vez)

  1. Descarga GitHub Desktop desde desktop.github.com e instálalo.
  2. Inicia sesión con tu cuenta de GitHub.
  3. Acepta la invitación al repositorio curso-robotica-2026 que recibirás por correo.

2. Clonar el repositorio (una vez)

  1. File → Clone repository.
  2. En la pestaña GitHub.com, selecciona juanuniovi/curso-robotica-2026.
  3. Elige la carpeta local y pulsa Clone.

3. Crear tu rama de fase

  1. Con master seleccionada, pulsa Fetch origin y, si aparece, Pull origin.
  2. Branch → New branch. Nombre: rol/fase-XX, por ejemplo sim/fase-05.
  3. Pulsa Publish branch.

4. Al empezar cada sesión: Fetch y Pull

  1. Pulsa Fetch origin.
  2. Si aparece Pull origin, púlsalo.

Trabajar sobre una copia desactualizada provoca conflictos con los cambios de otros miembros del equipo.

5. Al terminar cada sesión: Commit y Push

  1. En el panel Changes, deja marcados solo los archivos de tu rol. Desmarca los de otros roles y los de base/.
  2. Escribe el mensaje en Summary con el formato tipo(rol): descripción.
  3. Pulsa Commit to rol/fase-XX.
  4. Pulsa Push origin. Hasta ese momento los cambios solo existen en tu ordenador.

Mensajes correctos:

  • feat(is): añado tabla de stakeholders al análisis de la necesidad
  • fix(sim): corrijo unidades del puerto PotenciaElectrica
  • docs(tal): anoto ensayo de par del actuador según RLT1-09

Mensajes incorrectos: cambios, actualizado, asdf.

6. Al cerrar la fase: Pull request

  1. Branch → Create pull request. Se abre GitHub en el navegador.
  2. Destino: master. Describe brevemente el contenido.
  3. Quien tenga el rol de Sistemas revisa e integra el pull request.

Nombres de archivo

Sin espacios ni tildes, en minúsculas salvo siglas, con guion bajo como separador.

  • Correcto: analisis_necesidad_UGV.md, requisitos_ancla.csv, comprension_ESC.md
  • Incorrecto: Modelo Simulación Fase 5.slx, untitled3.slx, propulsion_final_DEFINITIVO_v3.slx

Problemas frecuentes

Aparece Conflict al hacer Pull.
No lo resuelvas por tu cuenta; avisa al profesor.
Aparecen en Changes archivos de otros roles.
Desmárcalos antes de hacer Commit.
Push desactivado o error de permisos.
Cierra sesión en GitHub Desktop y vuelve a entrar. Si persiste, avisa al profesor.
Se ha subido un archivo incorrecto.
No borres el historial. Corrige el archivo y haz un nuevo commit (fix(rol): corrijo …).
Un archivo .slx no abre o da error de versión.
Comprueba que usas MATLAB R2023b o posterior; los .slx no son compatibles hacia atrás.
